<objective>
Fix the pending build-state write race that crashed `pnpm run test:regression` on 2026-10-02. The error was `build-state: failed to read pending build state: Unexpected non-whitespace character after JSON at position 1867519`. Also make sure a stale or corrupt pending file left by an earlier run can never poison a new build.

Premise, verified on disk before planning: `.astro/build-state.pending.json` is 1,867,745 bytes. The first 1,867,519 bytes are complete, valid JSON. The remaining 226 bytes are the tail of a longer copy of the same structure, roughly five more article ids, also ending in `"changelog": {"count": 18}`. This is the signature of two writers holding separate file descriptors on the same file, with the shorter content landing over the longer. Both loaders (articles-loader.ts line ~399, changelog-loader.ts line ~284) call `writePendingBuildState` in one `astro build` process, and that function does an unlocked read, merge, then in-place `writeFile`.

The race also has a silent failure mode, which is worse than the crash. The changelog writer had read the previous build's article ids. If its write had simply finished last and cleanly, the pending file would have held a stale articles section. `commitLastGood` would then have recorded that stale section as the D-14 never-shrink baseline in KV, and nothing would have flagged it.

Purpose: restore the integrity of the D-14 never-shrink baseline (REND-02), and unblock the REND-05 byte-identity regression (criterion 3). Workers Builds caches `.astro/` between builds (D-06), so a corrupt file can carry over into production builds.

Output:
(1) Serialized, atomic pending writes in build-state.ts.
(2) A build-start reset, `tools/reset-pending-build-state.mjs`, run first in `pnpm run build`.
(3) Tests that fail against the current code for the race and pass after the fix.
(4) A real-build proof through `pnpm run test:regression`.

**Reset-point decision (Claude's discretion; this is the justification the task asked for).** The reset is the first command of `package.json` `scripts.build`.

Why there:
- `pnpm run build` is the one entry point shared by Workers Builds (ci-build's build step spawns it), the regression suite (which runs it directly and is the path that failed today), `test:unit`, and local builds.
- As the first command, it runs before any part of the current build. It therefore cannot discard state written by the current build.
- After it, a pending file can only have been written by the most recent `pnpm run build`. The deploy step (`ci-build deploy`, then `commitLastGood`) always runs after `pnpm run build` exits, in the same container.

Rejected alternatives:
- **ci-build's `markBuildStart`:** misses every direct `pnpm run build`, including the regression suite.
- **"First loader":** the two loaders run concurrently, so neither is reliably first.
- **An Astro integration hook:** whether the content-layer sync runs before or after a hook has not been verified for Astro 7, and `astro:config:setup` also fires for dev, sync and preview.
- **Treating a corrupt file as `{}` inside `writePendingBuildState`:** mid-build, a stale file can't be told apart from the current build's state, so this would be a silent discard.

ci-build.mjs is not modified. Its header guarantee that the ci-build process itself never loads build-state.ts during the build step still holds: the reset runs in the `pnpm run build` child, which already loads build-state.ts through both loaders.
</objective>
