<objective>
Make the REND-11 daily file-count report observable and retryable in production. A rejected ntfy send currently disappears without a trace: `defaultNotify` never checks the response status, the marker is written before anyone tries to send, and the deploy step's output never reaches the downloadable Workers Builds log.

Purpose: the production daily report has not arrived on 2026-10-01 or 2026-10-02. The topic, headers and server are proven fine: a manual POST using production's exact headers returned HTTP 200 and arrived. So the production send either fails or never runs, and nothing records which. After this plan:
(1) every send logs its HTTP outcome;
(2) a lost send no longer loses the day, because the marker is written only after a confirmed 2xx;
(3) the deploy step's lines, including those outcome lines, are no longer pushed out of the log by roughly 60k per-page `astro build` lines.

Output: changes to tools/ci-build.mjs and tools/archive-sync.mjs with tests (written test-first), one new real-spawn test file, and two doc corrections. No deploy, no Workers Builds trigger, no production R2 write and no real ntfy send happens during execution. Every network, process and R2 boundary is replaced by a fake.
</objective>
