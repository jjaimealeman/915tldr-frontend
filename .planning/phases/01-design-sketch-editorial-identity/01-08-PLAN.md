**Research corrections applied (RESEARCH Pattern 4 is incomplete):**
- It reads the `overflow` shorthand. Mixed values report as two words, so read `overflow-x` and `overflow-y` separately.
- It ignores `contain: paint` / `content` / `strict` and `clip-path`, both of which also clip.
- It ignores the viewport edge. At 320 px, a ring on an element touching the edge is clipped by the viewport.
- It does not check that the ring is visible against what is behind it.

**WebKit tab behaviour:** macOS WebKit only tabs to links when "tab to all controls" is on. Playwright's WebKit build may differ. The walk must not assume either way; it detects and records it (Task 1, step 3).

**Owner's pass:** these scripts provide coverage and regression checking. The owner's own keyboard walk in 01-10 judges tab order and operability, and constitutes the criterion-1 approval (D-14).

    1. Create `design/tests/support/focus.ts` with four exports.

       `enumerateFocusables(page)`: in-page, select `a[href], button:not([disabled]), input:not([disabled]):not([type=hidden]), select:not([disabled]), textarea:not([disabled]), [tabindex]:not([tabindex="-1"])`. Keep only elements that have client rects, are not inside a `hidden` ancestor, and whose computed visibility is not `hidden`. For each, return a stable path (tag plus `nth-of-type` chain) and an accessible name (`aria-label`, else normalised `innerText`, else `title`).

       `walkTabOrder(page, key)`: blur the active element, then press `key` repeatedly, up to the focusable count plus 5. After each press, record the active element's path and name. Stop when focus returns to a path already recorded. Return the sequence.

       `inspectFocus(page)`: in-page, for `document.activeElement`, return:
       - `focusVisible`: whether it matches `:focus-visible`;
       - `outlineStyle`, `outlineWidth` and `outlineOffset`, and whether `box-shadow` is set;
       - `ringBox`: the bounding rect grown on every side by outline width plus max(outline offset, 0);
       - `clippedBy`: the first ancestor, walking up to `html`, whose computed `overflow-x` or `overflow-y` is `hidden`, `clip`, `auto` or `scroll`, or whose `contain` includes `paint`, `content` or `strict`, or whose `clip-path` is not `none` — and whose padding box does not fully contain `ringBox`. The padding box is the ancestor rect inset by `clientLeft` and `clientTop`, with `clientWidth` and `clientHeight` as its size;
       - `outsideViewport`: `ringBox.left < 0` or `ringBox.right > innerWidth`, measured after the browser's own scroll-into-view;
       - `obscured`: true unless `document.elementFromPoint` at the element's centre returns the element or one of its descendants;
       - `ringColor` and `effectiveBackground`: the computed outline colour, and the computed `background-color` of the first ancestor, starting from the parent, whose background alpha is not 0. Fall back to the computed `--paper`;
       - `ringContrast`: the WCAG ratio of those two colours. Compute it in-page with the standard relative-luminance formula on the computed `rgb()` values; this is the one place where the browser's resolved sRGB is already given.

       `buildContactSheet(page, shots, caption, outPath)`: open a fresh page, `setContent` a grid of the shot PNGs (as data URLs) with captions (index, accessible name, key used), and screenshot the full page to `outPath`.

          - `outsideViewport` is false;

After the walk, write the contact sheet to `design/evidence/keyboard/<page>-<theme>-<width>-<engine>.png`, and merge the sequence into `design/evidence/keyboard/tab-order-<engine>.json` under page → theme → width, holding `{ tabKey, stops: [name…] }`.
