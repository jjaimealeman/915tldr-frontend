The block contract, consumed later by 01-18 (static pages), 01-21 (feed JSON plus the client renderer) and 01-22:
- Inline: an object with key `text` (a non-empty string) and an optional key `strong` whose only allowed value is `true`.
- Block: `{ "type": "p", "inlines": Inline[] }` or `{ "type": "list", "items": Inline[][] }`. No other keys are allowed.
- HTML serialisation (exact): each paragraph is `<p>` + inlines + `</p>`, where a strong inline is wrapped as `<strong>` + escaped text + `</strong>`. A list is `<ul data-key-details>` + one `<li>` + inlines + `</li>` per item + `</ul>`. Blocks are joined with a single newline. List items are joined with nothing. Only the characters `& < > " '` are escaped, as `&amp; &lt; &gt; &quot; &#39;`.

<feature>
  <name>Summary markdown → typed blocks → safe HTML</name>
  <files>design/scripts/lib/summary-markdown.mjs, design/tests/unit/summary-markdown.test.mjs</files>
  <behavior>
    Parsing rules:
    - Normalise CRLF to LF, then split the summary into blocks on one or more blank lines. Whitespace-only input gives `[]`.
    - Within a block, a line whose first two characters are U+2022 followed by a space is a bullet line. A run of consecutive bullet lines becomes one `list` block, and each item's text is the line with those two characters removed and trimmed.
    - A line whose entire trimmed content is a single `**…**` run, when directly followed by bullet lines, becomes its own `p` block with one strong inline (the corpus "Key Details:" label).
    - Any other lines in a block are joined with a single space into one `p` block.
    - Inside any paragraph or list-item text, each balanced `**x**` pair becomes a strong inline with text x, and the text around it becomes plain inlines. A `**` with no closing partner stays as literal text, with no strong produced.
    - Adjacent plain inlines are merged. Empty text runs are never emitted.
    - Lines starting with `- `, `* ` or a number followed by `. ` are NOT list items. They stay literal text, because the measured corpus uses only U+2022.

    Cases:
    - `''` → `[]`; `'  \n\n '` → `[]`
    - `'One sentence.'` → `[{type:'p',inlines:[{text:'One sentence.'}]}]`
    - `'A.\n\nB.'` → two p blocks
    - `'Prose.\n\n**Key Details:**\n• one\n• two'` → `[p('Prose.'), p(strong 'Key Details:'), list(['one'],['two'])]`, and renderSummaryHtml returns exactly `<p>Prose.</p>` + newline + `<p><strong>Key Details:</strong></p>` + newline + `<ul data-key-details><li>one</li><li>two</li></ul>`
    - `'The **big** day'` → inlines `[{text:'The '},{text:'big',strong:true},{text:' day'}]`
    - `'Price ** unmatched'` → one plain inline containing the two asterisks; the rendered HTML contains no strong tag
    - `'<script>alert(1)</script> & "q" \'a\''` → rendered HTML contains `&lt;script&gt;`, `&amp;`, `&quot;`, `&#39;` and no raw `<script`
    - `'Ciudad Juárez — niños, ñ, ü, “cita”…'` → the text is preserved code point for code point, and the rendered HTML contains those characters unescaped
    - The CRLF form of the Key Details case gives the same result as its LF form
    - `'•no space'` and `'- dash item'` → literal paragraph text
    - summaryPlainText joins each paragraph's text and each list item's text with `\n`
    - validateBlocks returns `[]` for any parseSummary output, and a non-empty problem list for `[{type:'h2'}]`, `[{type:'p',inlines:[{text:''}]}]`, `[{type:'p',inlines:[{text:'x',strong:false}]}]`, `[{type:'list',items:[[{text:1}]]}]` and `[{type:'p',inlines:[],extra:1}]`
    - Fixture sweep: for every object in stress-set.json's `cases` that has `uuid`, `status` and a string `summary`, parse and render without throwing. When the summary contains `**Key Details:**`: there is exactly one p block made of a single strong inline 'Key Details:', the next block is a list with as many items as there are bullet lines, and the whitespace-normalised summaryPlainText equals the whitespace-normalised source with every `**` removed and every bullet-plus-space prefix removed. For every summary, the rendered HTML contains no `**`.
    - Spanish sweep: every string field of every spanish-stress.json component survives parse and summaryPlainText with the same code points (whitespace normalised)
  </behavior>
  <implementation>Pure ESM, no dependencies, no I/O in the library. Exports: `escapeHtml(s)`, `parseSummary(markdown)`, `renderSummaryHtml(blocks)`, `summaryPlainText(blocks)`, `validateBlocks(value)` (returns string[]). The test file reads the two fixtures with node:fs.</implementation>
</feature>
