## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `fetch-fonts.mjs`'s `main()` ran unconditionally at import time**
- **Found during:** Task 2, first `npm run fonts:build`
- **Issue:** `build-fonts.mjs` imports `FILES` from `fetch-fonts.mjs` for manifest provenance; without an `isMain` guard, importing the module re-ran the entire network fetch+verify every time `fonts:build` ran.
- **Fix:** Guarded `main()` behind the same `isMain` pattern `serve-mockups.mjs` already uses.
- **Files modified:** design/scripts/fetch-fonts.mjs
- **Verification:** Re-ran `npm run fonts:build` — no duplicate fetch output; idempotency check (second run byte-identical) still passes.
- **Committed in:** `2a5d3d5`

**2. [Rule 1 - Bug] `openPage()`'s default `page.goto()` wait hung once font preloads existed**
- **Found during:** Task 2, first `verify:phase-1` run with `font-cls.spec.ts`
- **Issue:** `index.html`'s new `<link rel="preload" as="font">` tags delay the `load` event on a pending fetch, unlike an ordinary `@font-face`-triggered request — with `holdFonts()` deliberately holding those two requests open, `page.goto()`'s default `'load'` wait never resolved.
- **Fix:** `measureFontSwap` now navigates directly with `waitUntil: 'domcontentloaded'`, reusing `harness.ts`'s `blockThirdParty`/theme-seeding behaviour rather than its frozen `openPage()` export (which doesn't expose `waitUntil`, and is out of scope for this task to modify).
- **Files modified:** design/tests/support/geometry.ts
- **Verification:** Navigation now resolves immediately in both engines; full scoped run green.
- **Committed in:** `2a5d3d5`

**3. [Rule 1 - Bug] A literal `**/` inside a JSDoc comment closed the comment block early**
- **Found during:** Task 2, first test run
- **Issue:** `Routes **/fonts/*.woff2 and keeps...` inside a `/** ... */` block contains the substring `*/`, terminating the comment early and turning the rest of the docstring into broken executable code (`ReferenceError: fonts is not defined`).
- **Fix:** Reworded to avoid the sequence ("Routes every fonts/*.woff2 request...").
- **Files modified:** design/tests/support/geometry.ts
- **Committed in:** `2a5d3d5`

**4. [Rule 1 - Bug] `document.fonts` `FontFace.family` is never CSS-quoted, unlike `getComputedStyle().fontFamily`**
- **Found during:** Task 2, `measureFontSwap`'s pre-release assertion
- **Issue:** The assertion compared `FontFace.family` against a quoted string (`'"Instrument Serif"'`), which never matches — `.family` is always a plain DOMString. A second, related issue: requiring *every* declared `@font-face` for a family (including an unused italic variant) to reach `'loading'` was too strict, since unused style/weight variants correctly stay `'unloaded'`.
- **Fix:** Matched on the plain family name and restricted the check to actively-used variants (`status !== 'unloaded'`).
- **Files modified:** design/tests/support/geometry.ts
- **Committed in:** `2a5d3d5`

**5. [Rule 1 - Bug] WebKit defers all compositing/rAF while any `@font-face` resource is pending, invalidating the pre-swap "before" snapshot**
- **Found during:** Task 2, WebKit run of `font-cls.spec.ts`
- **Issue:** This specific Playwright-WebKit build (26.6, pinned Docker image) never fires a `requestAnimationFrame` callback — and, empirically, never composites a frame — while a primary font network request is held pending, regardless of `font-display: swap` and regardless of hold duration (verified up to 20s via an isolated debug page with a single minimal `@font-face` rule; a pending `<img>` request to the same URL does not reproduce it, confirming it's font-specific). Chromium composites and fires `rAF` normally. Consequence: a `snapshotLayout()` read taken before `release()` forces a synchronous layout the engine never actually painted — numbers with no corresponding user-visible state, not a real "before."
- **Fix:** `nextTwoFrames` now returns whether a real frame occurred (racing rAF against a fixed timeout); `measureFontSwap` only takes the real "before" snapshot when one did, otherwise reports `geometryScore: 0` (there is nothing to have shifted from, since nothing was ever shown) and sets the new `prePaintObserved: false` field so this is visible in the JSON evidence rather than silently assumed equivalent to Chromium's measurement. The separate pre/post-release "is the hold in effect" check (deviation 4, above) was also switched to network-level `pendingUrls()` tracking, since `document.fonts` FontFace status doesn't reliably update at all while WebKit's renderer is blocked this way.
- **Files modified:** design/tests/support/geometry.ts
- **Verification:** `design/.cache/font-cls-webkit.json` now honestly shows `prePaintObserved: false`, `geometryScore: 0`, `nativeSupported: false`, `nativeCls: null`, non-empty `fallbackFacesLoaded` — matching the plan's literal acceptance criteria without gaming the measurement. `design/.cache/font-cls-chromium.json` shows a genuine, small, real measurement (`prePaintObserved: true`, `geometryScore` 0.0003-0.0035, `nativeCls` 0-0.0001).
- **Committed in:** `2a5d3d5`
- **Flagged for human review:** see coverage item D8 above and "Known Stubs" below — this is a real, environment-specific finding, not independently confirmable against a real Safari device on this machine.

**6. [Rule 1 - Bug] An existing structure.spec.ts assertion assumed all browsers quote multi-word font-family names identically**
- **Found during:** Task 2, WebKit run of `structure.spec.ts` (a Task 1 file, not in Task 2's file list, but broken by Task 2's much longer capsize-generated font stack)
- **Issue:** `font.startsWith('"Instrument Serif"')` passed on Chromium (which preserves authored quoting) but failed on WebKit, which re-serialises `getComputedStyle().fontFamily` to the minimal-quoting form — omitting quotes around names like "Instrument Serif"/"Noto Serif"/"Times New Roman" that don't strictly need them (only forced-quoted names, like "Source Serif 4" with its trailing digit, or the capsize fallback names with a colon, stay quoted in both engines).
- **Fix:** Added a `firstFamily()` helper that strips optional surrounding quotes before comparing the first family name in the stack, applied to both the body-font and headline-font assertions.
- **Files modified:** design/tests/structure.spec.ts
- **Verification:** Both assertions pass in Chromium and WebKit.
- **Committed in:** `2a5d3d5`
