<objective>
Close 05-REVIEW CR-02. `pnpm run build` always partitions archive-tier pages out of `dist/client`,
but only `archive-sync pre` (inside `ci-build deploy`) uploads the newly archived ones or moves
failures back. The documented `pnpm run deploy` is `guard:config && wrangler deploy --config
wrangler.jsonc`, which skips pre entirely — every page that crossed the hot cutoff since the last CI
sync (~90 articles/day) and every tag that fell below 10 articles deploys as neither static nor in
R2, and 404s. Route the documented deploy through the real sequence, and make a partitioned dist/
undeployable through that sequence unless pre has confirmed this exact build. Fix the stale
build-start marker (IN-06) because the new route makes it reachable.

Purpose: REND-07/REND-08 (05-VERIFICATION.md gap 2: "Make the deploy script refuse to run without
a confirmed pre-sync marker, per CR-02's fix proposal").
Output: new guard tool, pre-sync marker, rewired deploy script and ci-build step, tests, docs.
</objective>

Design decisions (planner's discretion between the review's two proposals — both are used, as
layers):
- Route: `deploy` → `pnpm run guard:config && node tools/ci-build.mjs deploy`. `deploy:ci` and
  `ci:local` are unchanged; Workers Builds' configured commands (`build:ci`, `deploy:ci`,
  docs/phase-04/workers-builds-setup.md) are unchanged.
- Marker: `dist/archive-synced.json` (inside `dist/`, never inside `dist/client`, so it is never
  deployed), keyed to the plan's `generatedAt`, so a marker from an earlier build cannot vouch for
  a newer partition.
- The guard runs as a spawned child (`node tools/assert-archive-synced.mjs`), keeping ci-build's
  arm's-length convention (it spawns archive-sync/assert-file-count rather than importing them) and
  keeping every existing test's injected `spawnImpl` in control.
- Residual, out of scope and accepted: a bare `wrangler deploy` typed by hand, and the
  non-production "Version command" (`wrangler versions upload`, preview versions only) bypass the
  guard; wrangler.jsonc's own comment already forbids a bare deploy.

Execution rules (binding, same as 05-13): `/jja-commit` for every commit incl. SUMMARY metadata;
explicit staging; never branch/merge/rebase/push; tests use temp roots, `makeFakeStore` and
injected `spawnImpl`/`notifyImpl`/`commitImpl` only; nothing here deploys, runs `pnpm run deploy`,
or writes production R2; red before green.
