<objective>
Upload the archive tier to R2 safely and on time: a pre-deploy phase uploads pages that are new to
the archive (moving any it could not confirm back into the static output), and a post-deploy phase
re-uploads changed archived pages, deletes stale copies, and keeps a backlog and alerts so a
template-change re-render finishes within a day without ever holding up a deploy.

Purpose: REND-07 (archived pages rendered once and served from R2), D-09/D-11 (touched pages update
in the same cycle), D-10/REND-12 (full re-render in the background, bounded by the build ceiling),
D-12 (partial failure keeps the old copy and alerts).

Output: `tools/archive-sync.mjs`, `tools/lib/run-pool.mjs`, tests, `docs/phase-05/archive-architecture.md`.
</objective>

R2 bookkeeping objects (all under `_meta/`, which the Worker can never read — 05-03):
- `_meta/archive-index.json`: `{ version: 1, updatedAt, entries: { [key]: { sha256, bytes, path, uploadedAt } } }` —
  a record of confirmed uploads, read once and written once per phase (merge-on-write: re-read just
  before writing and apply only this run's changes, so a concurrent build can at worst cause a
  redundant re-upload later).

- `_meta/force-full.json`: `{ requestedAt, reason }` — present means "treat every archived page as
