<objective>
Make archive-sync's post phase refuse every path on which this build is not what production is
serving. Two review findings share one root cause — post-sync trusts its own local `dist/client`
instead of the live deployment:

- **CR-01 (second wall):** a dry run reaching post (05-13 closes the ci-build path; this closes a
  direct `CI_BUILD_DEPLOY_DRY_RUN=1 node tools/archive-sync.mjs post`).
- **WR-01:** overlapping or out-of-order builds — build A's post deletes key K that build B (now
  live) archived, 404ing it until the next pre re-uploads it.

The fix is a live-deployment match (`/version.json` commit + builtAt) before any R2 mutation,
re-checked just before deletions, plus an explicit dry-run refusal.

Purpose: REND-07/REND-08 (05-VERIFICATION.md gap 2: "Gate post-sync on a dry-run flag /
live-deployment match, per 05-REVIEW.md's CR-01 fix proposal").
Output: a fixed `tools/archive-sync.mjs`, regression tests, an updated architecture record.
</objective>

Facts measured during planning (2026-10-02):
- The build writes `dist/client/version.json` as `{"commit":"<7-char sha>","builtAt":"<ISO>","hashSource":...,"committedAt":...}`; the deployed site serves the same file at `https://dev.915tldr.com/version.json`. A local build and the deployed build differ in `builtAt` even at the same commit.
- `dev.915tldr.com` is the deployed Worker's only public origin until the Phase 12 cutover.

Execution rules (binding, same as 05-13): `/jja-commit` for every commit including the SUMMARY
metadata commit; explicit staging (`.gsd/`, `docs/screenshots/` stay untracked); never branch,
merge, rebase or push; unit tests use injected fakes only — NO real `fetch` and NO real R2 from any
unit test; nothing in this plan deploys or writes production R2. Red before green, failure quoted
in the SUMMARY.

Design decisions this plan implements (planner's discretion, recorded):
- Order inside `runPostSync`: plan read → dry-run refusal → `checkDisabled` (branch guard + R2
  credentials, unchanged) → liveness gate → `createStore`. A disabled run therefore still makes no
  network call at all; a non-live run makes one read-only GET and no R2 call.
- A non-live run skips EVERYTHING (uploads, deletions, state, daily report, force-full clearing)
  rather than only deletions: re-uploading "changed" pages from an undeployed build is also wrong
  (CR-01), and the live build's own post does that work.
- No override flag is added to force post against a non-live build. A manual `post` against a local
  build is now refused by design; documented in the architecture record.
</context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| archive-sync post → production R2 bucket | post holds delete/overwrite power over every archived page |
| archive-sync post → https://dev.915tldr.com/version.json | an untrusted network response decides whether post may act |
| local `dist/client` → post's orphan classification | local build state, which may not be what production serves |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-44 | Tampering | runPostSync on a non-live build (overlapping/out-of-order builds, WR-01) | high | mitigate | liveness gate before `createStore`; K-scenario regression test |
| T-05-45 | Tampering | direct `post` invocation during a dry run (CR-01) | high | mitigate | dry-run refusal before `checkDisabled`; createStore spy test |
| T-05-46 | Spoofing | a spoofed/stale `/version.json` making a non-live build look live | low | accept | an attacker able to serve a forged `/version.json` on the project's own origin already controls the site; https-only origin, exact commit+builtAt match, cache-busting query |
| T-05-47 | Denial of Service | origin unreachable → post skipped every build (daily report and orphan cleanup stop) | medium | mitigate | fails closed (no R2 change) and loud: one alert per build naming both versions; architecture doc names a persistent skip as an incident; Phase 12 cutover note |
| T-05-48 | Tampering | deploy landing between re-check and deleteObjects (residual TOCTOU) | low | accept | window reduced to one request; 05-18's pre self-heal re-uploads a key the index lists but R2 lacks |
| T-05-49 | Information Disclosure | alert/result text | low | mitigate | only commit/builtAt values and origin host appear; no credentials read by the check |
