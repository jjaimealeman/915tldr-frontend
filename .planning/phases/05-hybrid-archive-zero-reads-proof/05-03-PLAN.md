<objective>
Teach the Worker to serve the archive tier: on a static-asset miss, an archived article's canonical
URL is served from R2 using the manifest entry the Worker already reads (still one KV read), and an
archived tag page is served from R2 with no KV read at all. Responses match static pages' headers,
are cached briefly at the edge, and report their path in a Server-Timing header that the latency and
gate measurements (05-11, 05-12) read.

Purpose: REND-08 (archived requests fall through to the Worker and are served from R2) and the
structural half of ARCH-08 (≤1 KV read per request, small CPU path).

Design decision recorded here (Claude's discretion, CONTEXT "how R2 objects are keyed"): R2 keys are
derived from the validated uuid (`articles/<uuid>.html`) and slug (`tags/<slug>.html`) rather than
stored in a v3 manifest. RESEARCH proposed a manifest v3 with `tier`/`r2Key`; that is not done
because (a) the Worker already holds a validated articleId after its one KV read, so a stored key
adds nothing; (b) trying R2 for any canonical-path miss is race-free in both transition directions
(hot→archive and archive→hot) while a stored tier flag can disagree with the deployed assets for the
length of a build; (c) it avoids a schema bump that main's 2-hourly Phase 4 builds would fight over
in the shared KV namespace until Phase 5 merges.

Output: R2 binding, `archive-route.ts`, the extended Worker and redirect decision, unit tests, and a
test that drives the real wrangler-bundled Worker.
</objective>
