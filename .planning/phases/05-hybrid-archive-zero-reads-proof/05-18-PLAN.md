<objective>
Close 05-REVIEW WR-02: uncaught R2 failures in post-sync (and pre-sync) can leave
`_meta/archive-index.json` claiming objects that were deleted. If such a key later re-enters the
archive tier, pre-sync classifies it as unchanged/changed (not new), does not upload it, the deploy
removes it from static, and the Worker 404s — permanently if the content is unchanged. Make the
index self-healing at pre-sync, make every post-sync R2 failure an alert instead of a crash, and
make `deleteObjects` report partial results honestly.

Purpose: REND-07/REND-08 (the "never silently 404s due to the pipeline's own operations"
invariant, 05-VERIFICATION.md gap 2).
Output: fixed archive-sync and r2-client, regression tests, updated failure-mode table.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| archive-sync → production R2 (index, objects) | index truthfulness decides which pages leave the static tier |
| r2-client → callers | the delete result contract callers rely on to keep or drop index entries |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-60 | Tampering (integrity) | index claiming deleted objects → permanent 404 (WR-02) | high | mitigate | pre lists R2 once per run and re-uploads indexed-but-missing keys; post-then-pre regression test |
| T-05-61 | Denial of Service | uncaught R2 error crashing post/pre (exit non-zero, no RESULT line) | medium | mitigate | each post R2 call wrapped as an alert; pre index-write failure non-fatal; CLI `.catch` prints one line |
| T-05-62 | Repudiation | `deleteObjects` hiding which keys were deleted before a later batch failed | medium | mitigate | partial-result contract; failing batch keys reported per key |
| T-05-63 | Information Disclosure | error text from the AWS SDK | low | mitigate | only `describeError` (name/Code/status) is ever used in alerts and codes, never `err.message` |
</threat_model>
