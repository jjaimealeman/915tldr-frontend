<objective>
Give the repo the ability the verifier found missing — "the repo's tooling can't answer this" —
and use it to settle ARCH-08's CPU-outlier dispute. The project's gate record says one request
spiked to 49.966 ms; the orchestrator's independent Workers Observability query found four ≥ 20 ms
(49.966, 40, 37, 26 ms) plus one at 7 ms, all on archived-article paths. `tools/measure-worker-kv-cpu.mjs`
reads `workersInvocationsAdaptive`, which only returns aggregate quantiles/max, so it cannot list
or count requests (confirmed by the verifier via live schema introspection).

This plan builds a repeatable per-request tool on the Workers Observability telemetry API,
verifies that API's shape firsthand, runs it over the gate window, reconciles the counts, and
gathers the IN-01 correlation evidence (cold isolate vs request logic) — without deciding
anything. The owner decides in 05-19.
