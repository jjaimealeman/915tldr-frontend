# Phase 07 — UI Design Contract (Share Cards & Head Metadata)

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract.** Phase 7 changes NO page chrome (CONTEXT D-12): no header, nav, footer, layout, CLS or Lighthouse-visible change on any page. The visual surfaces are three, all outside the page DOM:

1. Two static share cards, `public/og-image.png` (EN) and `public/og-image-es.png` (ES), 1200x630 (D-05, D-06, D-07).
2. The icon set: `favicon.ico`, `favicon.svg`, 180px `apple-touch-icon.png` (D-13).
3. The head-metadata tag set in `src/layouts/Base.astro` (non-visual; contracted exactly in the Head Metadata Contract below).

Every number below was measured from `~/.claude/cache/og-card/v1-masthead.html` rendered in Chromium, or from the v1 asset files, on 2026-10-08. Where a measurement contradicts CONTEXT.md it is called out under Open Items rather than silently resolved.

Sources: CONTEXT.md D-01..D-20 (locked), ROADMAP Phase 7, REQUIREMENTS SOC-01..08, `src/styles/global.css`, `src/layouts/Base.astro`, `astro.config.mjs`.

### Card geometry (canvas 1200x630, both languages identical)

Focal point: the 188px "915 TLDR" wordmark (ink x 84..654, y 209..350) is the single focal point of the card. It is the largest element by a factor of about 4 over the tagline, so the eye lands on it first, and the tagline, rule and credit line step down from it in reading order.

Measured from the mockup; "ink" = rendered glyph/pixel extents, "box" = CSS box.

| Element | Position and size | Measured ink extent |
|---------|-------------------|---------------------|
| Logo mark (`logo-light.png`, 893x539 RGBA, transparent bg) | `width:150px`, `top:70px`; `left:78px` (see note) | ink x 92..226, y 77..154 at mockup `left:84` |
| Wordmark "915 TLDR" | `left:80px; top:190px`; Instrument Serif 400, 188px, line-height 1, letter-spacing -2px | ink x 84..654, y 209..350 |
| Tagline | `left:86px; top:392px`; Source Serif 4 italic 400, 46px, line-height 1.2 | EN ink x 86..503, y 401..447. ES ink x 85..635 |
| Rule | `left:86px; right:86px; top:500px`; 1.5px solid `#DDDEE0` | x 86..1114 (1028px wide) |

## Typography

Card only (the page chrome type system in `global.css` is unchanged). Exactly 3 sizes and 1 weight. The card declares one weight on purpose: Instrument Serif ships a single weight, and the tagline is the italic style at the same 400. Set `font-synthesis: none` so no browser fakes a bold.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (wordmark "915 TLDR", Instrument Serif) | 188px | 400 | 1.0 (letter-spacing -2px) |
| Heading (tagline, Source Serif 4 italic) | 46px | 400 (italic) | 1.2 |
| Label (credit line, Source Serif 4 roman) | 20px | 400 | 1.4 |
| Body | not used on the card | | |

Credit line is 20px, not the mockup's 24px. Measured reason: at 24px the Spanish credit line is 1175px wide, far beyond the 1028px rule, and wraps to two lines with an orphaned "enlace." that ends at x=1178 (22px from the canvas edge) and y=587 (21px above the stripe). The widths by size, measured in Chromium:

| Size | EN width | ES width | Fits the 1028px rule on one line |
|------|----------|----------|-----------------------------------|
| 24px (mockup) | 1061 | 1175 | no, either language (EN also overruns the rule's right edge at x=1114 by 33px) |
| 22px | 971 | 1072 | EN only |
| 21px | 936 | 1036 | EN only (ES over by 8px) |
| **20px** | **885** | **979** | **both** (ES has 49px slack) |

20px is the largest whole-pixel size where both languages sit on one line. Both cards use 20px so the footer zone is identical. See Open Item 4 for the owner re-approval this implies.

### Thumbnail legibility (D-19)

Scale factors applied to the final geometry. "Reads" is a prediction from downsampled renders of the V1 mockup; it is confirmed or overturned by the real-platform pass.

| Rendered card width | Scale | Wordmark | Tagline | Credit line | Required to read |
|---------------------|-------|----------|---------|-------------|-------------------|
| 600px | 0.50 | 94px | 23px | 10px | wordmark, tagline, credit |
| 300px | 0.25 | 47px | 11.5px | 5px | wordmark, tagline (credit not required) |
| 150px | 0.125 | 23.5px | 5.75px | 2.5px | wordmark only |

Rule: the wordmark and the tagline carry the identity, and the credit line is allowed to be illegible at thumbnail size. It is the attribution, and the same attribution text also lives in the page and in `og:description`, so nothing is lost when it is too small to read.

Pre-authorised contingency (not applied now): if the real WhatsApp, iMessage or Slack thumbnail shows the tagline unreadable, raise the tagline to 56px (EN ink right edge about x=600, ES about x=755; box bottom y=459, still 41px above the rule) and re-render. This needs a re-render and a re-validation, so it is not free, and it is only taken on evidence.

## Head Metadata Contract (`src/layouts/Base.astro`)

Non-visual, but it is the phase's primary deliverable. Emit exactly this set. Tag names and fixed strings are literal; `{...}` is computed, and `{origin}` is computed by the single rule in the `og:image` row below (it is not a literal).

### Placement and determinism

- Insert after the `alternate`/`robots` block and before the RSS `<link>`, in this fixed order: icons, `og:*`, `article:*` (articles only), `twitter:*`. One edit in the one layout covers every page.
- Builds must stay byte-deterministic (04-11a): no build hash, timestamp or randomness in any of these tags.
- Never emit a tag with an empty `content`. Omit the tag instead.

### Icons (every page)

```html
<link rel="icon" href="/favicon.ico" sizes="32x32" />
<link rel="icon" href="/favicon.svg" type="image/svg+xml" />
<link rel="apple-touch-icon" href="/apple-touch-icon.png" />
```

Root-relative is correct for icons. The `sizes="32x32"` on the `.ico` link keeps Chromium preferring the SVG.

### Open Graph (every page, including noindex, per D-14)

| Tag | Value |
|-----|-------|
| `og:title` | the page's `title` prop, verbatim (identical to `<title>`) |
| `og:description` | `description` prop, else `t('homeDescription', lang)` (exists in the dictionary, EN and ES). Never empty. |
| `og:url` | the canonical absolute URL (`canonicalHref`), always equal to the page's `<link rel="canonical">`. It is NOT affected by `SHARE_ORIGIN`: on dev it still points at the production origin. If the page has no `canonicalPath`, use `new URL(Astro.url.pathname, Astro.site).href` with the project's no-trailing-slash rule. |
| `og:site_name` | `915 TLDR` |
| `og:type` | `article` on article pages, `website` on every other page |
| `og:locale` | `en_US` for `lang='en'`, `es_US` for `lang='es'` |
| `og:locale:alternate` | the other locale. Emit on every page EXCEPT when `resolvedAlternates === 'self'` (an English page with no Spanish counterpart), where it would advertise a page that does not exist. See Open Item 3. |
| `og:image` | absolute HTTPS URL: `{origin}/og-image.png` (EN) or `{origin}/og-image-es.png` (ES), chosen by `lang` (D-11). **`{origin}` rule (exact, resolves former Open Item 2): `origin = SHARE_ORIGIN ?? Astro.site`**, with trailing slash stripped. `SHARE_ORIGIN` is a build-time environment variable, read once at build, set to `https://dev.915tldr.com` for dev deploys ONLY and left UNSET on prod, so on prod `origin = Astro.site = https://915tldr.com` (D-07 preserved) and on dev the tag points at the dev host that actually serves the new card. It is the same value for every page in a given deploy, so builds stay byte-deterministic (04-11a). It affects the `og:image` origin only, and nothing else in the head. |
| `twitter:image` (not emitted) | Not emitted, per the Twitter section below. X falls back to `og:image`, so the same `{origin}` rule governs the image X fetches. If the planner ever adds `twitter:image`, it must use the identical `{origin}` rule. |
| `og:image:width` | `1200` |
| `og:image:height` | `630` |
| `og:image:type` | `image/png` |
| `og:image:alt` | the alt string from the Copywriting Contract, by `lang` |

### Article extras (article pages only, D-15, D-16, D-18)

| Tag | Value |
|-----|-------|
| `article:published_time` | the same source value as `datePublishedIso` in `structured-data.ts` (ISO 8601). Never recomputed. |
| `article:modified_time` | the same value (published and modified are identical today, so it matches `dateModified` in the JSON-LD node). |
| `article:section` | the category display name in the page's language (`categoryLabel(slug, lang)`). Omit for an uncategorized article. |
| `article:tag` | one tag element per tag of THIS article, in the article's own order. Zero tags means zero elements. |
| `article:author` | absolute URL of `/about` (EN) or `/es/about` (ES) built with `localizedPath('/about', lang)`. No person's name, and never the originating outlet. |

New optional prop on `Base.astro` (not a second layout): an `article` object carrying `publishedIso`, `section`, `tags` and nothing else. When it is absent, no `article:*` tags and `og:type=website`.

### Twitter / X (every page, D-14, D-17)

| Tag | Value |
|-----|-------|
| `twitter:card` | `summary_large_image` |
| `twitter:image:alt` | same string as `og:image:alt` (recommended addition: not locked in CONTEXT, and X's fallback from `og:image:alt` is unverified, so one extra tag removes the doubt) |
| `twitter:site` | NOT emitted (D-17). No handle exists, so do not invent one. |

Do not emit `twitter:title`, `twitter:description` or `twitter:image`. X falls back to the `og:*` values for those (documented behaviour; confirm it in the X validator pass). Duplicating them is page weight with no benefit.

Weight note (estimate, to be measured by the planner): about 20 tags is roughly 1.2 to 1.6 KB uncompressed per page, across about 30k static pages. This is negligible next to the file-count budget but should appear in the build comparison.

## Interaction Contract

No interactive elements are added or changed. There is no hover, focus, keyboard or motion behaviour to specify, and `prefers-reduced-motion` is unaffected. The only "interaction" is a person pasting a link into a platform, so the contract for it is the validation matrix below.

### Validation matrix (D-19, D-20, SOC-07, SOC-08)

The owner pastes. The report records, for each cell: what rendered, the card variant seen (new or old v1), the origin the platform actually fetched (dev or prod; see Open Item 2), and "not checked" where applicable.

| Platform | EN page | ES page | Also record |
|----------|---------|---------|-------------|
| Facebook Sharing Debugger | required | required | whether the scraper fetched at all (D-20), warnings list, image dimensions it reports |
| X Card Validator | required | required | card type shown; whether alt is surfaced |
| iMessage | required | required | large vs small thumbnail; crop |
| WhatsApp | required | required | **rendered file size as a number (SOC-08)**; large vs small card; crop |
| Slack | required | required | unfurl image shown; alt text |

For every platform also look at: (a) the card at its smallest real thumbnail, using the legibility table above; (b) whether the platform shows a centre-cropped square instead of the 1.91:1 card. In a 630x630 centre crop (x 285..915), the "915" of the wordmark and the logo mark are cut off. This is not a failure by itself, because 1.91:1 is the standard `summary_large_image` shape. Record it if seen. Whether WhatsApp ever square-crops this image is unverified, so report it either way.

Candidate file sizes measured from the Chromium render: EN 43,228 bytes, ES 45,319 bytes (v1's old card is 316,894 bytes). Both are far below 5 MB. The SOC-08 number to record is what WhatsApp actually renders, not these.

Pre-cutover cache note: v1 is live today at `https://915tldr.com/og-image.png` (HTTP 200) with the old gradient card. Scrapers hold that cached image. ## Open Items

Item 2 is RESOLVED (an explicit decision, below). Items 1, 3 and 4 are OWNER-DECISION items: this contract applies a default so work is not blocked, but each needs the owner's sign-off and none is resolved by this document. Items 5 and 6 are validation-pass notes.

1. **OWNER SIGN-OFF NEEDED. v1 `favicon.ico` is the Nuxt logo.** Measured: `915tldr.com2/public/favicon.ico` is a 32x32 green Nuxt "mountain" mark. v1's `favicon.svg` is a blue "915" tile, a different design. D-13 says to port both. **Default applied here:** port `favicon.svg` verbatim and generate `favicon.ico` by rasterising that SVG (not by copying v1's file), and make the apple-touch-icon from the bubble mark as D-13 says. That leaves two different marks (blue "915" tile in browser tabs, bubble on iOS home screens), both as the owner specified. If the owner wants one identity, the alternative is to derive all three from the bubble mark, at the cost of a less legible 16px favicon. Needs a one-word owner decision at plan time.
2. **RESOLVED (decision, not an open question): `og:image` origin on dev.** Problem, measured on 2026-10-08: `astro.config.mjs` sets `site: 'https://915tldr.com'` on purpose, and the dev page's canonical is `https://915tldr.com/`. Production `/og-image.png` is v1's OLD gradient card (HTTP 200) and `/og-image-es.png` is a 404 until cutover. An `og:image` built from `Astro.site` alone would therefore point dev at prod, and the D-19 check on `dev.915tldr.com` could not show the new card.
   **Decision:** `og:image` origin = `SHARE_ORIGIN ?? Astro.site` (exact rule in the Head Metadata Contract `og:image` row). `SHARE_ORIGIN` is a build-time environment variable set to `https://dev.915tldr.com` for dev deploys ONLY and unset on prod, so prod uses `Astro.site` (D-07 preserved). It is deterministic per deploy (04-11a safe). `og:url` stays equal to the canonical and is unchanged by this rule.
   **Reporting consequence:** Facebook treats `og:url` as the canonical URL it scrapes (documented behaviour, not measured here), so a Facebook scrape of a dev page will report "scraped prod" (it fetched the v1 prod page). That result must NOT be counted as a v2 check. The validation report must name which origin each platform actually fetched, for every cell of the matrix.
3. **OWNER SIGN-OFF NEEDED. `og:locale:alternate` vs SOC-01 wording.** SOC-01 and D-14 say "every page". Emitting it on an English page with no Spanish counterpart (`alternates='self'`) would advertise a nonexistent page. Default applied: omit it in that one case only. Revert to literal "every page" if the owner prefers.
4. **OWNER SIGN-OFF NEEDED. Credit-line size change (24px to 20px) needs owner eye.** Forced by the Spanish string (measured, table above). EN would fit at 24px but overruns the rule by 33px, and mismatched footer zones between the two cards would look unintended. The owner approved the V1 mockup at 24px. The final PNG pair should be visually re-approved before it is committed. If the owner rejects 20px, the fallback is the ES line at 20px and the EN line at 24px, or a deliberate two-line ES footer with the rule and credit moved up (a layout change, not recommended).
5. **Facebook and X scraping of the noindex dev host (D-20)** remains unmeasured. It is a validation-pass item, not a design item.
