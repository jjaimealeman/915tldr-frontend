**`scripts/reprocess-execute.mjs`.** The gate, in order, before anything paid happens:
  1. `--report <path>` is required. No default, no discovery of "the newest report", no
     `--confirm` alternative. A flag that can be supplied instead of a report is the bypass D-15
     exists to remove.
  2. Load the report, re-derive the corpus fingerprint from the live corpus, and abort non-zero
     on any mismatch with a message naming both fingerprints.
  3. Take an exclusive run lock keyed to the report path — a lock file carrying the process id
     and start time. A second concurrent invocation exits non-zero without submitting. A stale
     lock from a crashed run is detectable by its recorded pid and is reported rather than
     silently stolen.
  4. Write a run manifest before the first paid call, and update it after every state change:
     the report path, the approved figures, the batch id once created, the ids submitted, and
     the ids written back. Resuming reads this manifest and retrieves the recorded batch instead
     of creating a new one — an interrupted run must never pay twice for the same work.

Then: run `checkGrounding` in `backfill` mode over the deterministically flagged candidates to
produce the confirmed set (the judge-stage spend the owner approved); union it with the
outage-window rows; build the JSONL; upload it; create the batch against the chat-completions
endpoint with the only supported completion window; and poll for completion.

On completion or expiry, fetch **both** the output file and the error file — an expired batch
still has completed work in its output file, and discarding it would pay for it twice.
Compute the expired remainder and submit a new batch containing only those entries, recording
each resubmission in the manifest. Repeat until nothing expired remains or a named maximum
resubmission count is reached, then stop and report rather than looping forever.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dry-run report file → paid execution | A file on disk authorises real spend against the owner's balance |
| corpus text → Batch JSONL file | Article content is serialised into a submission file where one malformed line can fail a whole corpus |
| provider batch results → production D1 | Model output is written back over summaries readers have already seen |
| re-processing run → published site | Content changes reach readers with no editorial step between |
