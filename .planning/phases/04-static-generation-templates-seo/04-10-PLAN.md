<planner_findings>
**Cold builds on Workers Builds are not optional, whatever the decision.** The Workers Builds
cache expires 7 days after last use and is invalidated whenever Astro decides the content config
changed; the loader also forces a cold resync every 7 days (04-03). So Workers Builds will run cold
builds on its own. The measured cold duration therefore decides feasibility for every option, not
only for "rebuild on Workers Builds". RESEARCH's 3.8–8.1-hour full-render estimate came from
Phase 3's per-page cost, which was dominated by one sequential KV PUT (338 ms) and one D1 read
(231 ms) per page; the pure render component measured 0.07 ms. The loader design removes both
per-page network calls, so 04-03/04-09's measured local cold build is the number to trust.
</planner_findings>
</context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub (public repo) → Workers Builds | Public source triggers credentialed builds |
| Deploy Hook URL | Bearer-style secret: anyone holding it can trigger builds |
| Workers Builds container → D1/KV/ntfy | Build token and topic live in build variables |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-39 | Information Disclosure | Public repo contents | high | mitigate | Before the owner's first push, `git grep -nE "(api[_-]?token|secret|password)\s*[:=]"` and a check that `.dev.vars` and `.env` are gitignored; no credentials in the tree (D-03) |
| T-04-40 | Spoofing / Denial of Service | Deploy Hook URL disclosure | medium | mitigate | Hook URLs kept only in `.dev.vars` and the backend secret store; never printed or committed; Cloudflare dedupes queued hooks and rate-limits to 10 builds/min per Worker (CONTEXT D-02) |
| T-04-41 | Elevation of Privilege | Build token scope | medium | mitigate | Token needs only Workers deploy, D1 read, KV edit; the setup doc tells the owner to confirm and not broaden further |
| T-04-42 | Tampering | Pull requests from forks triggering builds | medium | mitigate | Production branch `main` only deploys merged code (D-04); owner reviews non-production build settings for fork PRs and leaves fork builds disabled |
</threat_model>
