<objective>
Make the second half of the phase goal true: when something looks wrong on the live site, you
can tell which layer is lying. `/version.json` answers it for a script, the footer answers it
for a human, and both read the same number so they cannot disagree.

Purpose: OPS-05 and OPS-06 are cheap to implement and easy to implement dishonestly — a
`git rev-parse` in a shallow CI checkout returns a hash that was never deployed, and a footer
that computes its own timestamp will drift from the one `/version.json` reports. Either
failure is worse than having no stamp, because a wrong stamp is trusted. OPS-08 puts the read
budget where someone debugging will actually find it.

Output: one build-info module, two surfaces that agree, a test that proves they agree, and a
README that states the budget in numbers rather than adjectives.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build environment → public artifact | `/version.json` and the footer are read by humans and scripts as authoritative statements about what is deployed. Whatever the build believes becomes a public claim. |
| public internet → static asset layer | `/version.json` is a prerendered file served without invoking the Worker; it exposes a commit hash and a build time, and nothing else. |
