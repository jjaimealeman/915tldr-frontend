## What Changed

- File: `src/lib/summary.ts`
  - Added `splitStandfirst()` — extracts the summary's opening sentence (Phase 1 D-10 standfirst
    deck) using `Intl.Segmenter('en-u-ss-standard', { granularity: 'sentence' })`, with a fixed
    non-terminal abbreviation list (U.S., Dr., Mr., Mrs., Ms., St., Jr., Sr., Gov., Sen., Rep.,
    Lt., Sgt., Capt., No., a.m., p.m., and the AP month abbreviations) merging back the sentence
    boundaries ICU's own heuristic gets wrong
  - Added `summaryBodyHtml()` — drops the standfirst sentence, renders the rest through
    `design/scripts/lib/summary-markdown.mjs`'s existing block contract, appending a `keyPoints`
    list only when the summary carries no inline "Key Details:" block of its own
- File: `src/lib/rail.ts`
  - Added `computeRails()` — owner-selected option-a (2026-09-26 checkpoint): one pass over the
    collection, sorted `publishedAt` desc/`uuid` asc, producing each article's "more" (same-
    category neighbours published before it) and "second" (site-wide neighbours published before
    it, heading "Earlier")
  - Added `railFingerprint()` — stable join of each neighbour's render inputs, for detecting when
    a rail's rendered HTML would change even though the article's own data digest did not
- File: `tests/unit/summary.test.mjs`
  - Fixed one test fixture (the "St." abbreviation case unintentionally also contained "N.",
    which is not in the non-terminal abbreviation list and correctly triggered a real sentence
    break there — the test's own construction, not an implementation bug)

## Why

Phase 4 Plan 04, Task 2 (tdd="true"): the article template (Task 3) needs standfirst/body
splitting and rail neighbour selection as pure, tested functions before it can be wired in. Both
modules implement the owner's checkpoint decision (option-a, article-relative rail) rather than
the mockup's site-wide "Latest" list, which would defeat criterion 3 (byte-identical unchanged
articles) by baking today's newest stories into every one of ~40,000 static pages.

## Issues Encountered

The first "St." test fixture also contained "N." (a street-initial abbreviation not in scope per
the plan's own named abbreviation list), which produced a real early sentence break at "N." — not
an implementation bug, just an overloaded test fixture. Fixed by removing the "N." token from that
one fixture; no production code changed for this.
