## What Changed

- File: `src/lib/build-info.ts` (new)
  - Exports `BUILD_HASH`, `BUILD_TIMESTAMP`, `BUILD_HASH_SOURCE` — resolved once at module
    evaluation, which runs in Node during `astro build` since this module is imported from
    prerendered pages
  - Exports `resolveBuildHash(env)` as a pure function (the resolution order as a testable
    contract, not module-evaluation-time side effect) implementing the order: prefer
    `WORKERS_CI_COMMIT_SHA`; fall back to `git rev-parse --short=7 HEAD` only when neither `CI`
    nor `WORKERS_CI` is set; otherwise `'unknown'`
  - `BUILD_HASH_SOURCE` records provenance (`'workers-ci' | 'local-git' | 'unknown'`) so a
    fallback-derived stamp can never be mistaken for a platform-vouched one
- File: `src/pages/version.json.ts` (new) — static `GET` endpoint returning
  `{ commit, builtAt, hashSource }` read from the three build-info constants, prerendered by the
  project default (`output: 'static'`) so it lands as a real file in `dist/client/`
- File: `src/layouts/Base.astro`
  - Footer's `<p data-build>` now renders `BUILD_HASH` and a date sliced out of
    `BUILD_TIMESTAMP`, replacing the literal placeholder `build 0000000 · 2026-09-16` carried
    over from 03-01. No second clock read in the layout — the date comes from the same timestamp
    `/version.json` reports

## Why

OPS-05/OPS-06 are cheap to implement dishonestly: a `git rev-parse` in a shallow CI checkout can
name a commit that was never deployed, and a footer with its own `new Date()` call drifts from
whatever `/version.json` reports for the same build. One module, read twice by two surfaces, is
the only way they cannot disagree — this task centralizes both values in `src/lib/build-info.ts`
so neither `/version.json` nor the footer computes anything of its own.

Established as part of this task (see `03-03-SUMMARY.md` for the full record): this project's
own deploy path is local `wrangler deploy`, not git-connected Cloudflare Workers Builds — the
account's two existing Workers (`915tldr`, `915tldr-dev`) both return zero build history against
the Workers Builds API, and this repo has no `.github/` directory and no configured git remote.
So in real practice `hashSource` resolves to `'local-git'` today; the `'workers-ci'` path is
implemented in full and exercised by Task 2's test, ready for if the deploy pipeline ever moves
to Workers Builds CI.
